# AGENTS.md

This repository is a Vite + TypeScript + Three.js browser game repo for npm-built games that deploy separately from `AlanCoding.github.io`.

## What this repo is

- The app root is [index.html](/home/arominge/repos/gravity-games/index.html).
- Source lives in [src/](/home/arominge/repos/gravity-games/src/).
- Shared browser/game primitives live under [src/engine/](/home/arominge/repos/gravity-games/src/engine/).
- Individual games live under [src/games/](/home/arominge/repos/gravity-games/src/games/).
- Track Planet is the first game and lives under [src/games/track-planet/](/home/arominge/repos/gravity-games/src/games/track-planet/).
- The main personal site is expected to link here at `/gravity-games/#track-planet`.

## Deployment model

- This repo is prepared for GitHub Pages via GitHub Actions.
- The workflow is [.github/workflows/deploy-pages.yml](/home/arominge/repos/gravity-games/.github/workflows/deploy-pages.yml).
- GitHub Pages should be configured as: Settings -> Pages -> Source: GitHub Actions.
- Pages serves the built `dist` artifact uploaded by CI. It does not serve the repo root.
- Do not commit `dist/`; it is generated by CI and ignored locally.

## Vite base path

- The GitHub Pages base path is configured in [vite.config.ts](/home/arominge/repos/gravity-games/vite.config.ts).
- The default base path is `/gravity-games/`.
- If this repo is renamed, update `VITE_BASE_PATH` or the documented default. For example, if the repo is named `track-planet`, the base should be `/track-planet/`.

## Project conventions

- Use Vite, TypeScript, and Three.js.
- Do not add React unless there is a clear need.
- Keep the app mounted in a normal page container; do not assume fullscreen-only behavior.
- Keep game-specific code, assets, and markdown under that game's `src/games/<game-id>/` folder.
- Keep only genuinely reusable 3D/game infrastructure under `src/engine/`.
- Keep planning and design markdown under `planning/`, organized by topic or game.
- Preserve the custom physics boundary. Do not add Rapier or another built-in gravity engine unless explicitly requested.
- Achievement integrations should stay behind placeholder callbacks or small adapter modules until the target achievements system is clear.
- After each completed response that changes the repo, create a git commit with a concise message that describes the change.
- If a requested change reveals a logical refactor opportunity, prompt the user with the refactor idea and ask for a yes/no go-ahead before doing it.

## Validation

- Install dependencies with `npm ci`.
- Run `npm run build` before handing off changes.
- Use `npm run dev` for local development and `npm run preview` to inspect the production build.
- Do not start `npm run dev` or `npm run preview` unless the user explicitly asks; the user prefers to run local servers themselves.
